Come funzionaHow it works

Un orchestratore, specialisti nascosti, script per il resto.

One orchestrator, hidden specialists, scripts for the rest.

L'orchestratore pianifica, apre gli stage con la tua conferma, delega con brief autosufficienti e consolida i report nel piano della POC.

The orchestrator plans, opens stages with your confirmation, delegates with self-contained briefs and consolidates reports into the POC plan.

  • Gli stage non si aprono per inferenza: il target ambiente sta nel piano e lo conferma l'utente.
  • Stages never open by inference: the target environment lives in the plan and is confirmed by you.
  • Due sotto-agenti non lavorano mai sullo stesso artefatto; più generative page vanno in parallelo.
  • Two sub-agents never touch the same artifact; multiple generative pages run in parallel.
  • Ogni report distingue verificato, non verificato e simulato.
  • Every report separates verified, unverified and simulated.

FAQ

Domande frequenti.

Good questions.

Serve un ambiente Dataverse per iniziare?Do I need a Dataverse environment to start?

No. Lo stage P produce un prototipo statico con dati sintetici: bastano Node.js e un browser. L'ambiente serve solo dallo stage R, dopo la tua conferma.

No. Stage P produces a static prototype with synthetic data: Node.js and a browser are enough. An environment is only needed from stage R, after your confirmation.

Posso usare dati reali del cliente?Can I use real customer data?

No. I dati demo sono sempre sintetici; il validator dei dati segnala email non su domini demo, IBAN e codici fiscali.

No. Demo data is always synthetic; the data validator flags non-demo email domains, IBANs and Italian tax codes.

Cosa impedisce di toccare l'ambiente sbagliato?What stops it from touching the wrong environment?

Il preflight confronta i profili attivi con il piano e si ferma se non coincidono; l'hook poc-guard chiede conferma prima di cancellazioni, cambi di profilo e import. Nessuna cancellazione senza autorizzazione esplicita.

The preflight compares active profiles with the plan and stops on mismatch; the poc-guard hook asks before deletions, profile switches and imports. No deletion without explicit authorization.

Model-driven o code app?Model-driven or code app?

Se la UI nasce da record, viste e moduli, model-driven (con generative page e PCF nei punti custom). Se il valore sta in un'interazione disegnata su misura, code app. Nel dubbio si parte da model-driven.

If the UI comes from records, views and forms, model-driven (with generative pages and PCF where custom). If the value is a bespoke interaction, code app. When in doubt, start model-driven.

È adatto a un progetto di delivery?Is it meant for delivery projects?

No: è pensato per POC e demo in ambienti DEV. Le decisioni di datamodel e i contratti YAML però diventano una specifica utile per chi implementa.

No: it targets POCs and demos in DEV environments. Data model decisions and YAML contracts still become a useful specification for the delivery team.

Funziona con Claude Code?Does it work with Claude Code?

Il plugin usa il formato di GitHub Copilot (VS Code e Copilot CLI). Gli script sono Node puro e funzionano da qualsiasi terminale.

The plugin uses the GitHub Copilot format (VS Code and Copilot CLI). The scripts are plain Node and run from any terminal.
